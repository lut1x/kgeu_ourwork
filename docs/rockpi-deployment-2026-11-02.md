# Rock Pi 4A: установка шлюза 2 ноября 2026

- Плата: `192.168.1.69`, hostname `rockpi-4a`, ARM64 (`aarch64`).
- ОС: Armbian 26.8.0-trunk.94 / Debian 13, Python 3.13.5.
- Установлен `raspberry-gateway/`, версия 1.0.1. Это Python-шлюз с протоколом `scada-uart-v1`; пересборка под ARM64 не требуется.
- Новый адрес сервера в конфигурации: `https://170.168.150.194`, стандартный HTTPS-порт 443, проверка сертификата включена.
- Служба `scada-gateway.service` запущена и включена в автозапуск. Исходники: `/opt/scada-gateway`, защищённая конфигурация: `/etc/scada-gateway/gateway.env`.
- Помимо автоматического поиска USB-UART настроен `/dev/ttyS2`. Serial-getty на этом порту при установке неактивен. Загрузочные overlays не менялись; электрическое подключение и обмен с физическим датчиком требуют отдельной проверки.
- Установлен системный пакет `python3-serial` для ARM64. Все три теста прошли непосредственно на плате, включая Linux pseudo-UART и сохранение/повторную доставку очереди.
- SQLite: `/var/lib/scada-gateway/queue.sqlite`, проверка целостности `ok`.
- Включён `scada-gateway-backup.timer`; первый согласованный снимок создан в `/var/backups/scada-gateway`. Хранятся семь снимков.

После готовности параллельно установленного сервера плата зарегистрирована как `Rock Pi 4A (192.168.1.69)`, collector ID `1`. Ключ сохранён только в закрытых файлах на плате и на сервере (`/root/scada-collectors/rockpi-4a.env`).

Проверено около 12:09 МСК: сервер получает свежий heartbeat, версия шлюза `1.0.1`, порт `/dev/ttyS2`, очередь `0`, поле ошибки пустое. Плата получила конфигурацию по HTTPS с проверкой сертификата: `115200` бод, каналы пока не назначены. После синхронизации создана дополнительная резервная копия. Реальные показания датчика и физический UART этим тестом не проверялись.

Проверка на плате:

```sh
systemctl status scada-gateway --no-pager
journalctl -u scada-gateway -n 30 --no-pager
systemctl list-timers scada-gateway-backup.timer
```
