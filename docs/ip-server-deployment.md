# Чистая установка по IP

Адрес: https://170.168.150.194 — Debian 13, проект `/opt/tech-scada`.
Домен `нашскада.рф` (`xn--80aaap2aq3a9c.xn--p1ai`) подготовлен к автоматической активации. Владелец добавляет DNS-запись `A` для `@` со значением `170.168.150.194` после активации регистрации. `scada-domain.timer` каждые пять минут проверяет DNS; когда домен указывает только на этот IP, выпускает отдельный сертификат, подключает nginx, обновляет адрес в письмах и отключает свою проверку. Доступ по IP сохраняется. Если существует посторонняя запись AAAA, её нужно удалить. Статус: `journalctl -u scada-domain.service -n 30 --no-pager`.
Используется отдельный `docker-compose.ip.yml`, новая база MySQL 8.4 и новые ключи шифрования и приёма телеметрии. Данные предыдущего сервера не переносятся. Исходные демонстрационные датчики удаляются только при первой установке с проверкой отсутствия пользователей и показаний; симулятор не запускается.

Команда `scada` на сервере выбирает эту конфигурацию и защищённый файл `/opt/tech-scada/.env.local`:

```sh
scada ps
scada logs --tail=60
scada restart
```

Внешние порты: 22 (SSH), 80 (перенаправление на HTTPS и проверка сертификата), 443 (приложение). MySQL и backend не публикуют порты наружу. Вход администратора сохранён локально в игнорируемом файле `.server-access/new-server-login.txt`. Для почты использована существующая SMTP-конфигурация проекта.

Проверены публичный HTTPS по IP, перенаправление HTTP, вход администратора, защищённые cookies, пустой каталог, права администратора, экспорт и WebSocket. Первоначальная резервная копия повторена после создания администратора. SMTP Gmail с нового сервера пока недоступен: TCP-подключения к портам 465 и 587 завершаются по тайм-ауту. По указанию владельца подтверждение при регистрации удалено: аккаунт оператора создаётся сразу, без DNS и SMTP. Почтовый сброс пароля пока требует восстановления SMTP-связи.

Для сервера с 550 МБ RAM добавлен swap 1 ГБ; MySQL, backend и nginx имеют отдельные лимиты памяти. Интерфейс собирается на компьютере. Backend использует Node.js 22. Такая конфигурация рассчитана на небольшую нагрузку.

Сертификат Let's Encrypt выдан непосредственно на IP. Короткий срок действия требует автоматического продления: `scada-certbot.timer` проверяет его каждые шесть часов. Проверка HTTP проходит через `/var/www/acme`; hook перечитывает сертификат в nginx. Порт 80 должен оставаться доступным.

Автозапуск: Docker restart policies и `scada-stack.service`. Ежедневная резервная копия базы и env-файла в 06:30 по Москве: `/var/backups/tech-scada`, хранение семь суток. Эти копии находятся на том же сервере; для восстановления после потери сервера их нужно сохранять отдельно вместе с ключом шифрования.

```sh
systemctl list-timers scada-certbot.timer scada-backup.timer
systemctl start scada-backup.service
/opt/certbot/bin/certbot renew --dry-run
df -h /
docker stats --no-stream
```

Не выполнять `scada down -v`: эта команда удаляет базу.
