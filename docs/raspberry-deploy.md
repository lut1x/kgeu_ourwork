# Raspberry Pi → SCADA

В панели администратора появился раздел **«Платы и устройства»**. Поддерживаются Raspberry Pi 2 Model B v1.1 с 32-битной ОС и Rock Pi с Linux. На плате работает Python, без Docker и базы MySQL.

## Первый запуск

1. Установить Raspberry Pi OS с Python 3.9 или новее, подключить Ethernet, включить синхронизацию времени. Для USB-UART настройка GPIO не нужна. Для GPIO включить UART и отключить последовательную консоль через `raspi-config`.
2. Открыть SCADA → «Платы и устройства» → добавить шлюз → сохранить показанный ключ.
3. На Raspberry скачать и установить:

```sh
curl --fail --show-error --location https://scada.lut1x1337.ru:9443/downloads/scada-raspberry-gateway.tar.gz -o scada-raspberry-gateway.tar.gz
tar -xzf scada-raspberry-gateway.tar.gz
cd raspberry-gateway
sudo sh install.sh
```

Установщик запросит адрес SCADA и ключ. При обновлении сохраняются существующие ключ, настройки и очередь. Дальше служба сама стартует после включения питания.

4. В прошивку своего ESP32 добавить `esp32_scada.h`. В `setup()` вызвать `Serial.begin(115200)`, после измерения тока — `scadaPublishCurrent(currentMa)`. `currentMa` — реальное откалиброванное значение в мА. Для второго канала использовать `scadaPublishCurrent(currentMa2, "current_2")`.
5. Подключить ESP32 через USB-UART к Raspberry. В панели появятся его ID, канал и порт. Нажать «Добавить в SCADA», выбрать группу, название, единицы и физический диапазон. Для входного тока оставить вход 4–20.

Для датчика давления 0–10 бар: физический минимум 0, максимум 10, единица bar, входной минимум 4, максимум 20. При 12 мА панель покажет 5 бар.

После первоначальной установки обнаружение устройств, подключение каналов и изменение масштаба выполняются в панели. Данные начинают сохраняться после назначения канала. Произвольные UART-датчики без поддерживаемого протокола автоматически не определяются. Схема измерения тока и калибровка АЦП ESP32 зависят от вашего оборудования и в этот шлюз не входят.

## При обрыве связи

Для назначенных каналов Raspberry сохраняет показания в SQLite и передаёт после восстановления связи. Каждое измерение имеет UUID и исходное время. Сервер подтверждает записи и исключает дубликаты. Накопленные старые значения не заменяют текущие показания на панели.

Лимит очереди и локального архива — 250000 записей на плату (около 69 часов при одном измерении в секунду суммарно). При заполнении новые значения сохранить нельзя, ошибка отражается в статусе и журнале. Архив отключённых каналов сохраняется; при возврате назначения записи отправляются повторно. Перед изменением масштаба следует дождаться пустой очереди: накопленные исходные значения пересчитываются по настройкам на момент загрузки.

Состояние платы и устройств определяется по последнему обмену; через 60 секунд без обновлений выводится отсутствие связи/данных. Проверка устройств пассивная, без команд на UART. Открывать входящие порты на Raspberry не требуется. Замена ключа, настройка сети и обновление самой службы требуют доступа к плате.

```sh
sudo systemctl status scada-gateway
sudo journalctl -u scada-gateway -f
```

Настройки: `/etc/scada-gateway/gateway.env`, очередь: `/var/lib/scada-gateway/queue.sqlite`. Для нестандартного GPIO UART задать `UART_PORTS=/dev/нужный_порт` и перезапустить службу. Одновременно поддерживается до 32 последовательных портов и 64 обнаруженных каналов.

## Проверки

API проверен на локальном стенде с MySQL: привязка каналов, отдельные ключи плат, пересчёт, повторная доставка, оригинальное время, отзыв ключа, отключение шлюза и сохранение прав пользователей. 16 октября 2026 шлюз установлен на физическую Raspberry Pi 2 с DietPi: проверены pseudo-UART, SQLite, HTTPS до VPS, защита от дубликатов, восстановление зависшего процесса и автозапуск после перезагрузки. Подробности: [отчёт установки](dietpi-deployment-2026-10-16.md). Реальный аналоговый вход и ESP32 ещё не проверены: устройство пока не подключено.
