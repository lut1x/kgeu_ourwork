# Развертывание SCADA

Адрес: https://scada.lut1x1337.ru:9443

## Обновление шлюзов 15 октября 2026

Развёрнуты новый API `/api/collector/v1/` и раздел администратора «Платы и устройства». [Инструкция Raspberry / ESP32](raspberry-deploy.md). Публичный установочный архив: `https://scada.lut1x1337.ru:9443/downloads/scada-raspberry-gateway.tar.gz`, SHA-256 `a060a6eb9a991326553a1e58543432561bd365b3af9619c26deee7b52f6591c2`.

Проверены через публичный HTTPS: вход администратора, обнаружение ESP32, удалённая привязка, пересчёт 12 мА в 5 бар, сохранение исходного времени, исключение дубликатов и отображение в каталоге. Временные тестовые данные удалены. На физической Raspberry и аналоговом входе ESP32 проверка ещё не проводилась.

Перед обновлением выполнена штатная резервная копия. Предыдущие образы сохранены с тегом `gateway-before-20261015`, предыдущие исходники — в `/var/backups/tech-scada/gateway-20261015/source-before.tar.gz`. Откат приложения: `sh /var/backups/tech-scada/gateway-20261015/rollback.sh`. Новые таблицы при откате не удаляются. Прежний симулятор продолжает работу со своими каналами.

Сервер: Debian 13, 147.45.238.163, SSH 22. Проект размещен в `/opt/tech-scada`.

Используются `docker-compose.server.yml` и `docker-compose.small-server.yml` вместе. Команда `scada` на сервере автоматически выбирает оба файла и `.env.local`.

```sh
scada ps
scada logs --tail=80
scada restart
docker stats --no-stream
```

Xray остался на 443, x-ui на 8443. SCADA публикует только 9443; MySQL и backend доступны внутри сети Docker. Порт 80 используется Certbot для выдачи и продления сертификата.

Для 1 ГБ RAM добавлен swap 2 ГБ `/swap-scada`; контейнеры имеют лимиты RAM/CPU, журналы ограничены 3 файлами по 10 МБ. MySQL использует буфер 64 МБ и максимум 20 соединений. Argon2id сохраняет параметры защиты; `UV_THREADPOOL_SIZE=1` ограничивает параллельную обработку хешей. Это конфигурация для небольшой учебной нагрузки, а не проверенная многопользовательская производственная установка.

Существующие 3 пользователя, 6 датчиков, группы, назначения и история перенесены из локальной БД. Сессии и незавершенные подтверждения очищены только в серверной копии: требуется новый вход.

Запущен демонстрационный симулятор с интервалом 10 секунд. Это не физические датчики.

```sh
scada --profile demo stop simulator
scada --profile demo up -d --no-build simulator
```

Образы собраны на Windows-компьютере в Docker Desktop и перенесены как `tech-scada-backend:deploy`, `tech-scada-frontend:deploy`, `tech-scada-simulator:deploy`. Не запускайте сборку на маленьком сервере. Для обновления сначала соберите и перенесите новые образы с компьютера, затем выполните `scada up -d --no-build`.

Certbot timer включен; hook `scada-reload` проверяет nginx и перечитывает сертификат только для домена SCADA. Проверка продления:

```sh
certbot renew --cert-name scada.lut1x1337.ru --dry-run
```

Ежедневная резервная копия базы и `.env.local` сохраняется в `/var/backups/tech-scada` в 06:30 по Москве. Файлы старше 7 суток автоматически удаляются только из этой папки резервных копий. История датчиков автоматически не удаляется. Резервная копия настроек VPN и firewall перед установкой Docker находится в `/root/scada-deployment-backups`. Серверные копии нужно дополнительно переносить на другой носитель.

```sh
systemctl start scada-backup.service
systemctl status scada-backup.service
systemctl list-timers scada-backup.timer certbot.timer
df -h /
```

Секреты находятся в `.env.local` (права 600). Локальный SSH-ключ, миграционная копия БД и архивы находятся в игнорируемой папке `.server-access`. Не отправляйте эти файлы в Git или в чат. Для расшифровки восстановленной БД нужен соответствующий `ACCOUNT_ENCRYPTION_KEY`.

Не используйте `down -v`: он удаляет том MySQL. Не запускайте скрипты первоначального импорта повторно поверх используемой базы.
